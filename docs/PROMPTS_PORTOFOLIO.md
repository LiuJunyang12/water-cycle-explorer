# Water Cycle Explorer — 开发提示词总结 / Ringkasan Prompt Pembangunan

> 用途：向讲师说明「这个网站是怎么一步步做出来的」。
> 说明：下表每一节对应开发的一个部分，**一节只保留一条提示词总结**（由开发过程中的多次对话归纳而成，保留原始意图与关键约束）。右栏「我的原创决策」是学生在提示词里自己定下的规则、取舍与教学设计，不是工具默认行为。

---

## 1. 项目立项与开发规则

**提示词**
> 做一个给马来西亚五年级学生（Sains Tahun 5，Unit 8 Jirim，SP 8.2.3/8.2.4）的水循环互动学习网站，一共七个页面：首页、冒险地图、任务开始、科学实验室、循环构建器、科学家挑战、反思。用我提供的 Wally 水滴吉祥物和插画，走自然系卡通风格；马来文为主、关键术语后面括注英文。**不能有假交互**：进度、徽章必须真的对应学生做过的事；素材全部由我自己提供，你不要自己生成或找替代；最后要能放进 GitHub 当公开静态网站。

**我的原创决策**
- 七个页面围绕「一趟探险旅程」串成故事线，而不是七个独立练习。
- 自己定下三条科学红线：水蒸气不可见、云由微小水滴/冰晶组成、太阳能量驱动蒸发。
- 要求「进度必须真实」，因此坚持用 localStorage 记录每一站的完成时间。

**产出**：`PROJECT_RULES.md`（十章开发规范）、页面路由结构。

## 2. 首页与整体视觉

**提示词**
> 首页用我给的插画做背景（背景要模糊、标题要清楚），中间放标题和一颗会轻轻跳动的「MULA PENGEMBARAAN」按钮；左上角放圆形菜单键，右上角放黑胶唱片控制背景音乐（我准备了两首，可以切换）；菜单里做三个毛玻璃弹窗：学生资料、离线电子书、学习目标。

**我的原创决策**
- 双 BGM（可爱风 / 中国风）由学生自己选，选择记在浏览器里。
- 考虑课室电脑可能禁自动播放，要求「先静音播放、学生第一次点击后再出声」。
- 学生资料弹窗要放我真实的姓名、学号、讲师资料，让它像一份正式的电子作品集封面。

**产出**：`HomePage`、`MenuButton` / `MenuDrawer`、`MusicPlayer`、`InfoDialogs`。

## 3. 冒险地图（解锁机制）

**提示词**
> 把地图做成真正的探险地图：六个站点按故事顺序解锁，**没完成前一站就不能进下一站**，锁住的站要告诉学生「先完成哪一站」；顶部显示真实进度「x/6」，完成的站打勾。站点图标不能遮住地图上的地标，地图尽量占满屏幕；右下角放一个圆形返回首页的按钮。

**我的原创决策**
- 解锁规则写成纯函数（`getStationStatus`），保证「跳站不会解锁」而不是靠界面装作锁定。
- 站点徽标做小、站名挂在下方的做法，是为了不破坏地图插画。
- 进度用 localStorage 持久化，同一台电脑重开浏览器还在。

**产出**：`AdventureMapPage`、`src/data/stations.ts`、`src/hooks/useProgress.ts`。

## 4. 第 1 站：Stesen Khemah（影片站）

**提示词**
> 第 1 站放科普影片，**必须看完才算完成**，看完弹出三道马来文引导问题，让学生先说一说再进下一站；进入这一站时背景音乐自动暂停，离开再恢复。

**我的原创决策**
- 把「看完」的门槛从 97% 提高到 **100%**，并要求用影片结束事件吸收播放器的取整误差，避免学生差 0.3 秒就过不了。
- 用三个开放式问题代替选择题，先让学生开口说，再接后面的游戏。

**产出**：`CampStationPage`、`src/data/campStation.ts`。

---

## 5. 第 2 站：Pantai Cerah（阳光捕手）

**提示词**
> 第 2 站做成一个小游戏：把太阳拖到水滴上方去照射它，水滴就会被蒸发；全部水滴蒸发完就通关；水面要随着蒸发真的下降。桌面上不能把水面裁掉，学生要能看全整个场景。

**我的原创决策**
- 除了鼠标拖拽，还要求支持键盘方向键，方便没有触控板的课室电脑。
- 加入「雾」的视觉提示，但坚持不是画白色蒸汽柱——对应「水蒸气不可见」的红线。
- 宽屏适配问题是我自己发现并提出的（截图反馈「看不到水滴」）。

**产出**：`SunChaseScene`、`src/game/sunChase.ts`。

---

## 6. 第 3 站：Cloud Kingdom（云端跑酷 + 关卡内测验）

**提示词**
> 第 3 站做成 2D 平台跑酷：Wally 在云上跳过断桥、躲开气流障碍，一共三关；第一关通过后考一题，第二关通过后做排序题，答对了云桥才会出现，然后进第三关。**画面要固定不动，只有角色在动**，学生放大窗口也不能把画面压扁或出现左右空白。

**我的原创决策**
- 「固定镜头、只让角色动」是学生提出的取舍：这样所有物体的大小都适配屏幕，不会因为窗口比例变形。
- 主动要求降低移动速度（从 58 降到 34），因为五年级学生操作需要更宽容的容错。
- 提出「**看得见就撞得到**」的判定原则：判定盒必须等于插画实际画出来的身体，而不是隐形的小方块；火焰因此整体上移到头顶以上，保证走路能过、跳起来才被烧到。

**产出**：`CloudKingdomPage`、`CloudQuestScene`、`src/game/cloudQuest/{levels,physics,flow}.ts`、`ScienceQuiz`、`OrderingChallenge`。

## 7. 第 4 站：Lembah Air Terjun（聚水成云 → 降雨）

**提示词**
> 第 4 站：天空漂着很多小水滴，学生把它们拖到云上的大水滴里，水滴会变大、云会越来越黑；全部合进去之后云开始上下摇（撑不住水的重量），然后问学生「云已经撑不住了，要不要开始降雨？」，点 Yes 播放一段下雨过场，很多水滴往下降，落进海、湖、河。**Wally 不要放在旁边的说明栏**，把 Wally 放进场景里，用弹出的对话一句一句讲原理。

**我的原创决策**
- 把「解释文字」改成 Wally 的角色对话，是学生自己的教学设计：学生看雨的时候不会去读侧栏，所以让角色在画面里说。
- 要求降雨过程放慢到约 25 秒（每句解说 4.2 秒），让学生有时间观察，而不是一闪而过。
- 用「云变黑 → 摇晃 → 征求同意」三步，把抽象的「降水」变成有因果的身体感受。

**产出**：`WaterfallValleyPage`、`RainCloudScene`、`src/game/rainGather.ts`。

## 8. 第 5 站：Stesen Kitaran Air（排序 + 图示标注）

**提示词**
> 第 5 站做两层互动：先给四张画着场景的卡片，学生把「蒸发、凝结、降雨、汇聚」排成正确顺序；排对之后出现一张水循环图（有天空、海、云、雨、河），下方是词牌，学生要把词拖到图上对应的位置——蒸发放海、凝结放云、降雨放雨、汇聚放河。

**我的原创决策**
- 每张卡片都要求画出「那个过程的场景」，而不是只写一个词，让学生靠图判断过程。
- 排错时不直接告诉答案，只标出哪些位置错，鼓励重试。
- 同样遵守红线：蒸发卡片只画太阳加热水面 + 上升箭头，**不画白色蒸汽**。

**产出**：`WaterCycleStationPage`、`WaterCycleDiagram`、`CycleCardArt`、`src/game/waterCycle.ts`。

---

## 9. 第 6 站：Makmal Cabaran Sains（问答测验）

**提示词**
> 第 6 站是 Q&A 问答测验，只做选择题，大约 8 题。最重要的是设计：多加好看的插画和图片、emoji，让整个画面可爱生动，设计成 Wally 提问、下面出现四个选项。每题用我给的图，**图片外面不要蓝色底板，只看到图片本身**。

**我的原创决策**
- 8 题分别对上一个水循环过程，答案位置打散，避免学生找规律猜答案。
- 每题答完立即给解释（不只是对错），把测验变成「即时反馈的学习」。
- 通过标准取 80%（8 题需 7 题），可重试、以最好成绩计，符合我原本定的徽章标准。

**产出**：`ChallengeLabPage`、`QuizArt`、`src/game/quizLab.ts`、`public/assets/images/challenge-lab/*`。

## 10. 最终环节：Majlis Anugerah（颁奖典礼 + 证书）

**提示词**
> 第 6 站答完后不要出现「回到地图」，改成另一个按钮，进去最终环节：Wally 从侧边缓缓走出来，宣布颁奖给玩家、恭喜他成为优秀的水循环科学家（用对话框）；然后 Wally 请学生留下名字，学生点 OK 后弹出窗口写名字，接着屏幕出现一张证书给他看，而且可以下载，**证书上要有学生输入的名字**。

**我的原创决策**
- 把「颁奖典礼」当作整趟旅程的收束，而不是一个分数页。
- 证书内容由我指定：姓名、奖衔「SAINTIS AIR CEMERLANG」、三枚徽章（Penjelajah / Pembina Kitaran / Saintis）、日期、签名栏。
- 后续自己发现「下载 PNG 不能用」，要求学生端改用 **PDF** 下载（老师可直接打印）。

**产出**：`FinalePage`、`CertificateCard`（纯 SVG 证书）、`src/utils/certificateDownload.ts`（PNG 绘制 → PDF 封装）。

## 11. Google Drive 学习报告（老师后台）

**提示词**
> 每个玩家答完题、填名字拿到证书后，把他刚才的答题数据报告存进我 Google Drive 的一个文件夹里，当作后台数据库，老师可以随时查看学生的表现。

**我的原创决策**
- 要求报告不只看总分，还要有「每题选了什么/对不对」「第 1–5 站完成情况」「开始冒险到交卷用了多久」，方便老师看出学生卡在哪。
- 要求断网时不能让学生卡住：先存在本机，下次打开站点自动补发。
- 明确「这份是给老师看的」，所以用老师自己的 Drive 文件夹 + 表格，而不是让学生注册账号。

**产出**：`src/data/reporting.ts`、`docs/REPORTING.md`（Apps Script 全文 + 部署步骤）、报告表格 12 列。

## 12. 离线电子书

**提示词**
> 把我准备的电子书 PDF 放进网站，学生可以下载，也可以直接在浏览器里阅读；另外在首页放一个「查看电子书」的入口，不用点开菜单也能找到。

**我的原创决策**
- 下载时统一存成 `E-book-Kitaran-Air.pdf`，不用学生面对原始的中文长文件名。
- 弹窗里显示体积（约 12 MB），让学生知道要下多久。
- 首页入口做成小一号的玻璃胶囊，放在主按钮上方，不抢「开始冒险」的注意力。

**产出**：`public/assets/ebook/offline-ebook.pdf`、`InfoDialogs` 双按钮、`HomePage` 入口。

## 13. 重制第 1 站影片（自己写脚本合成）

**提示词**
> 原来的开场影片是英文的第三方动画，我要换成自己的：用我提供的插画素材，做一段约 95 秒的马来文影片，内容参考原影片的逻辑——太阳加热 → 蒸发 → 看不见的水汽 → 凝结成云 → 降雨 → 汇流 → 循环，最后问学生三个问题，让 Wally 当讲解员。

**我的原创决策**
- 决定不用第三方 IP，全部用自己画的 Wally 与插画重做（学术诚信）。
- 自己定分镜与每段时长，把 3 分钟的英文片压到 95 秒的马来文核心概念片。
- 主动要求「水蒸气那一段不要画白雾」，改用向上的箭头表示看不见的水汽。

**产出**：`tools/build-video-1.ps1`、`public/videos/khemah-video.mp4`（1080p / 95 s / 7.6 MB）、`docs/VIDEO_STATION1.md`。

## 14. 全站视觉统一与可用性修正

**提示词**
> 把全站所有的「Kembali ke peta」文字按钮，都改成第一站那种圆形地图图标按钮，整体更简约；另外固定位置的菜单键和黑胶片会遮住画面内容，请调整内容位置，确保不会被遮挡。

**我的原创决策**
- 统一成一个共享组件，而不是每页各写一份，保证以后改一次全站生效。
- 顶部让出固定安全区（`--chrome-clearance`），让每一页的标题都不会被菜单键/唱片压住。

**产出**：`BackToMapButton`、`--chrome-clearance` 令牌、第 1–5 站样式统一。

## 15. 发布上线

**提示词**
> 把网站放到 GitHub，再导入 Vercel 发布成公开链接，过程中要手把手教我每一步。

**我的原创决策**
- 决定仓库 **public**，但 `design-assets/` 原始素材（168 MB）与 `.env` 不上传，只上传运行需要的文件。
- 发布前先自己清理体积：把 108 MB 只用于剪片的源图移出 `public/`，部署包从 151 MB 降到 21 MB。
- 环境变量（报告端点）用 Vercel 注入，而不是把它写进仓库。

**产出**：GitHub 仓库 `LiuJunyang12/water-cycle-explorer`、Vercel 公开链接、`docs/DEPLOY_VERCEL.md`、`tools/push-to-github.cmd`。

## 附：这个网站上「属于我自己的创意」

| 类别 | 具体做法 |
| --- | --- |
| 教学设计 | 七个页面 = 一趟探险旅程；先看影片 → 再动手玩 → 再排卡片 → 最后测验与颁奖 |
| 抽象概念具象化 | 把「蒸发」变成拖太阳、「凝结」变成把水滴聚到云上、「降水」变成云黑到撑不住 |
| 科学严谨 | 自定三条红线（水蒸气不可见、云由小微粒组成、太阳供能），并贯穿全部页面与影片 |
| 角色运用 | Wally 不是装饰：地图向导、跑酷主角、对话讲解员、颁奖主持人 |
| 真实状态 | 进度、解锁、徽章、证书全部来自真实操作与 localStorage，没有假按钮 |
| 教师视角 | 学生答题报告自动汇入老师的 Google Drive 表格，含逐题作答与旅程用时 |
| 可用性 | 看满 100% 才算完成、看得见就撞得到、固定镜头不变形、断网可继续、手机也能用 |
| 学术诚信 | 不用第三方影片与素材，全部使用自己绘制并经处理的原创图 |
